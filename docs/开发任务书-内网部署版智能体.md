## 0. 一页总览

**做什么**：在内网部署一个"电气接口智能体"Web 服务——工程师用浏览器访问，能查电气链路、看变更影响、跑质量体检，可选接内网大模型做自然语言对话。**不依赖 Comac Claw 平台**（Claw 对接是后续可选适配器，见 T8）。

**两个里程碑**：
- **8/25**：v1 内网可部署——三个 Skill（链路追踪 / 变更影响 / 质量体检）+ Web UI + 部署文档；有模型则带对话，没模型则纯表单模式，两种形态都算达标；
- **9/25**：十个 Skill 全量 + MCP 化 + 评测达标发布。

**三条铁律（先读这个再写代码）**：
1. **零第三方依赖**：只用 Python 3.8+ 标准库（内网机器没有 pip）。sqlite3、http.server、urllib、json 够用，已有代码全部如此；
2. **只读**：智能体对数据库只读（连接串用 `file:...?mode=ro`），任何写操作都是 bug；
3. **数据红线**：只允许使用脱敏库 `eicd_anon.db`。原始快照 `eicd_snapshot_*.db` 和映射表 `etl/mapping_anonymize.json` 永不离开数据负责人机器，也永不进代码引用。

## 2. 总体架构

```
浏览器（内网任意机器）
   │ HTTP
┌──▼───────────────────────────────────────────┐
│ agent/reference/server.py                     │
│  ThreadingHTTPServer（纯标准库）              │
│  ├─ GET /            → ui/index.html 单页界面 │
│  ├─ POST /api/skill/trace    (S03)            │
│  ├─ POST /api/skill/impact   (S04)            │
│  ├─ POST /api/skill/quality  (S08)            │
│  ├─ POST /api/chat   → llm.py 函数调用循环    │
│  └─ GET  /api/health                          │
│                                               │
│  skills.py（三个确定性内核，不依赖大模型）    │
│  eicd_tools.py（约12个只读查询工具+SQL沙箱）  │
│  llm.py（OpenAI兼容适配，未配置时优雅降级）   │
└──────┬────────────────────────────────────────┘
       │ sqlite3 只读
   data/eicd_anon.db          可选: 内网大模型
                              (OpenAI兼容 /v1/chat/completions)
```

设计理由：对话层是"锦上添花"，三个 Skill 的价值在确定性管道里——模型没到位，表单模式已经能交付使用；模型到位，改一个配置文件就升级成对话模式。

## 3. 任务分解（按顺序做，T1–T5 是 8/25 交付的关键路径）

### T1 工具层 `agent/reference/eicd_tools.py`（预估 1.5 天）
约 12 个只读函数，直查 `eicd_anon.db`。对照 `chat-tools.ts` 移植：
`list_projects / search_devices / get_device_detail / search_connectors / get_connector_detail / search_pins / get_pin_connections / search_signals / get_signal_detail / search_wires / get_harness_summary / get_change_history / run_readonly_sql`
- `run_readonly_sql`：只放行单条 SELECT（拒绝分号多语句/PRAGMA/ATTACH），强制追加 `LIMIT 100`，连接用 `sqlite3.connect("file:...?mode=ro", uri=True)`；
- 中文列名一律双引号包裹（如 `"设备部件所属系统（4位ATA）"`）；
- **验收**：用 `eval/gold/auto_eval_v0.jsonl` 里的 48 条金标逐条核对——工具返回必须与 gold 一致（写个 20 行的核对脚本跑一遍，全绿为过）。

### T2 三个 Skill 内核 `agent/reference/skills.py`（预估 2 天，全项目技术含量最高的部分）
- **S03 `trace_signal(ref)`** 链路追踪：输入信号 unique_id 或设备编号。取信号端点（设备/连接器/针孔/输入输出方向）→ 取实现导线（wires.signal_id）→ 每根导线两端（wire_ends：pin 侧关联到设备针孔，ic_pin 侧关联到互联点）→ 经 `interconnect_pin_pairs` 贯通对把跨分离面的导线段连成链。连通性算法直接搬 `relink-wire-signals.py` 里的并查集。输出 JSON：`{signal, endpoints[], segments[], separation_surfaces[], gaps[]}`（gaps=逻辑边没有物理导线兑现的段）；
- **S04 `impact_analysis(device_ref | connector_ref)`** 变更影响：目标设备/连接器 → 下属针孔 → 落在这些针孔上的信号端点 → 信号 → 对端端点所在设备（及其 `设备负责人`）→ 实现导线 → 所属线束。输出：受影响信号/设备/导线/线束清单（各带总数，明细截断到 50 条）+ 需通知责任人列表 + 该实体变更历史条数；
- **S08 `quality_check(project_id?)`** 质量体检，四项检查（都是单条 SQL 可实现的简化版，完整版 9 月再对齐平台 QA 脚本）：①信号边两端针孔"端接尺寸"不一致；②有逻辑边但无实现导线的信号；③未挂信号的导线；④出现在信号端点上但"端接尺寸"为空的针孔。输出：`{summary:{四项计数}, samples:{每项≤20条明细}}`；
- **验收**：用信号 `N240279-340014` 自测 S03——正确输出应含 2 个端点设备（U-2403 应急配电盘箱 → 2U-341 甚高频设备2）、2 根导线（W3303-34023-14/34024-14）、2 处分离面（D33002-A1、D33004-A2）。S04 用 U-2403 自测，受影响信号数应 >0 且包含上述信号。

### T3 服务与 UI `server.py` + `ui/index.html`（预估 1.5 天）
- `ThreadingHTTPServer`，路由见架构图；所有 /api 返回 `application/json; charset=utf-8`；
- UI 单页自包含（内联 CSS/JS，无 CDN——内网没外网）：左侧四个页签（对话/链路追踪/变更影响/质量体检），表单提交 → 结果渲染成表格；对话页签在 `/api/health` 报告 llm 未配置时置灰并提示；
- 界面样式可参考 `0814会议准备材料/02-交付物展示.html` 的设计变量（配色/字体栈直接抄）。

### T4 LLM 适配 `llm.py`（预估 1 天，可与 T3 并行）
- 用 `urllib.request` POST 到 OpenAI 兼容端点 `{base_url}/v1/chat/completions`；配置从 `config.json` 读（格式见 §4），环境变量 `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL` 可覆盖；
- 函数调用循环：把 T1 的工具集 + T2 的三个 Skill 以 OpenAI tools 格式暴露给模型，循环执行 tool_calls 直到模型给出文本回答，上限 6 轮；系统提示词里写入本体摘要（22 类/关系语义，从 `ontology.md` 精简 30 行）；
- 端点不支持函数调用时的退化路径：把工具清单写进提示词，让模型输出 `CALL 工具名 {json参数}` 行协议，正则解析执行；
- 未配置/连不上：`/api/chat` 返回明确错误码，UI 引导用户用表单模式。**对话不可用不阻塞 8/25 验收。**

### T5 部署打包（预估 0.5 天）
- 写 `agent/reference/内网部署说明.md`：拷贝清单（`agent/reference/` 整个文件夹 + `data/eicd_anon.db`）、启动命令 `python server.py --db ..\..\data\eicd_anon.db --port 8087`、防火墙放行、LLM 配置方法、"只读/脱敏库/局域网内使用"三条安全边界；
- 在一台**没装过任何 pip 包**的内网机器上从零走一遍部署文档，走不通就改文档。

### T6 评测跑分（预估 0.5 天，8/25 前完成）
- 写 `eval/score.py`：读金标 jsonl → 逐条调 T1/T2 的工具 → 对比 gold → 输出通过率报告到 `eval/reports/`；
- 8/25 验收线：查询/核查类 ≥85%（按当前实现应为 100%，达不到说明有 bug）。

### T7 MCP 化（9 月第一周，预估 2 天）——把 T1/T2 包装成 MCP stdio server（`mcp/eicd-graph`、`mcp/eicd-analysis`），JSON-RPC over stdio 手写即可，协议简单；供 Claw 或其他 MCP 宿主调用。
### T8 Claw 适配器（条件触发）——拿到 Claw 接入规范后做，预估 1–2 天：图谱格式导出（参考 `graph/adapters/export_neo4j.py` 的模式）+ Skill 包格式转换。**规范不来不做，不阻塞任何节点。**

## 7. 常见坑（前人踩过的，别再踩）

- 中文列名含中文括号（`设备部件所属系统（4位ATA）`），SQL 必须双引号包裹，Python 里当普通字符串处理；
- Windows 控制台打中文会 GBK 乱码：调试输出写文件（UTF-8）或 `sys.stdout` 重包一层，别信 print；
- `signal_endpoints.端接尺寸` 列已废弃，端接尺寸唯一事实在 `pins.端接尺寸`（平台 2026-07 的"方向A"决策）；
- 一个信号可有 >2 个端点（一发多收）、可被多根导线实现（双芯/屏蔽），S03 不要假设一对一；
- 屏蔽线 `wires.is_shield=1` 无独立信号归属，拼链路时按缆号（cable_no）跟随芯线。
